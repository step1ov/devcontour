# Roadmap: поток изменений для панели

Дата: 18 ноября 2026 года.

Статус: не начат. Сейчас панель опрашивает сводку, обзор автора, центр
внимания и экран подготовки каждые 2–3 секунды из каждой вкладки. Сервер
отвечает «без изменений» по ревизии или метке (`revision`, `etag`) и считает
каждую проекцию один раз на версию данных (F60), но опрос остаётся: запрос
на каждый интервал, задержка изменения до интервала опроса и пересчёт по
пределу возраста ответа, даже когда ничего не изменилось.

## 1. `GET /api/stream`: ревизия и изменившиеся области

Сервер отдаёт поток server-sent events: событие — номер ревизии данных и
список изменившихся областей (`summary`, `overview`, `attention`,
`preparation`, детали задачи по id). События объединяются за окно около
250 мс: серия записей одного такта — одно событие. Поток проходит те же
проверки Host и Origin, что и прочие маршруты `/api/`, и ничего не пишет.

Приёмка:

- запись состояния, локальная запись и отметка присутствия ведущего дают
  одно событие за окно объединения с ревизией и областями, которые она
  меняет;
- простаивающий сервер событий не шлёт, кроме редкого heartbeat;
- истечение lease, после которого ответ области меняется без записи, тоже
  даёт событие этой области;
- остановка сервера закрывает поток, переподключение получает текущую
  ревизию первым событием.

## 2. Панель перезапрашивает только изменившиеся области

Приёмка: при открытом потоке панель запрашивает область только по его
событию (с прежней ревизией или меткой) и не опрашивает её по таймеру.
Обрыв потока возвращает опрос с прежними интервалами; восстановление
потока снова его отключает. Тесты: событие одной области не вызывает
запросов других; обрыв и восстановление потока; несколько вкладок
получают одно событие на изменение.

## 3. Опрос остаётся запасным путём

Приёмка: клиент без поддержки потока, прокси, обрывающий долгие ответы, и
агентский API работают прежним опросом с «без изменений»; протокол
`revision`/`etag` не меняется.
