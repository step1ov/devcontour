# Roadmap: панель на ограниченных проекциях

Дата: 9 октября 2026 года.

Статус: P01–P07 реализованы (решение D35); результаты измерений — в разделе 6. Идентификаторы P01–P07 новые.

## 1. Проблема

Панель разработки каждые 1,8 с запрашивает `GET /api/state` и получает всё состояние целиком:

- все попытки с evidence, findings, таймингами и patch;
- все ChangeSet с проверками и полными снимками задач;
- все контракты с текстом, вся история досок и восстановлений;
- последние 150 событий.

Ответ растёт с каждой попыткой и проверкой и никогда не уменьшается. Сервер на каждый опрос читает и сериализует всё состояние. Браузер на каждый опрос разбирает весь ответ, даже если ничего не изменилось: признака ревизии нет. Пагинация есть только у карточки договора проверки.

## 2. Baseline

Обезличенный fixture `tests/large-history.ts`. Основа — настоящий прогон учебного демо, размноженный: 82 доски, 287 задач, 767 попыток (у каждой третьей задачи четыре отказавшие попытки с диагностикой), 60 ChangeSet по 3 проверки, 20 000 событий. Измерено на macOS, Node 24, Chromium из Playwright, desktop 1440×900.

| Показатель                        | Baseline                                          |
| --------------------------------- | ------------------------------------------------- |
| Размер ответа `/api/state`        | 13,7 МБ (503 КБ в gzip; сервер не сжимает)        |
| Время ответа `/api/state`         | медиана 136–176 мс, p90 460–580 мс                |
| Трафик API за 30 с опроса         | 219–232 МБ (из них `/api/state` — 16–17 запросов) |
| Первая доска видна после загрузки | 0,9–1,8 с                                         |
| Открытие доски / задачи           | 146 мс / 41 мс (всё уже в памяти)                 |
| Main thread за 30 с опроса        | TaskDuration 1,5–1,9 с                            |

## 4. Работы

- **P01. Ревизия состояния.** Монотонный номер изменения (id последнего события журнала). Периодический ответ принимает `since` и при совпадении возвращает только номер.
- **P02. Периодическая проекция `GET /api/summary`.** Компактные строки досок с прогрессом, задачи выбранной доски с последней попыткой в виде компактной строки, активные попытки, компактный список ChangeSet и контрактов без текста. Плюс пауза, ожидания, workflows, ready, часть конфигурации и последние события. Тела evidence, логи, findings, patch, снимки задач проверок и история восстановлений сюда не входят.
- **P03. Детали по запросу.**
  - задача — полная запись и страницы попыток;
  - попытка — evidence с хвостами логов;
  - ChangeSet — последняя проверка и страницы прежних, снимок задач по запросу;
  - контракт — текст;
  - журнал событий — страницами;
  - сводка прогресса — агрегаты на сервере.
- **P04. Клиент.** Панель опрашивает только проекцию и загружает детали при открытии; полный `/api/state` из периодического опроса убран. Если детали не загрузились, показывается ошибка с повтором. Сбой опроса виден, следующий успешный опрос восстанавливает состояние. Навигация по доскам и задачам и прямые ссылки работают.
- **P05. Совместимость.** `/api/state` остаётся внутренним интерфейсом доверенной консоли и CLI, но панель его не опрашивает. Agent API не меняется.
- **P06. Измерение.** Повторяемый замер на fixture: размер и время ответов, трафик за окно опроса, время до первой доски и открытия задачи. Результат сравнивается с целями раздела 3.
- **P07. Тесты.**
  - ответ проекции ограничен и не содержит тел истории;
  - удвоение истории не увеличивает ответ сверх строк новых досок и ChangeSet;
  - «без изменений» по ревизии;
  - пагинация и пределы деталей;
  - e2e: навигация, открытие задачи, ошибка деталей с повтором, восстановление после сбоя опроса, отсутствие `/api/state` в периодическом трафике.

## 5. Вне объёма

Server-sent events и websockets, кэш на стороне сервера между процессами, виртуализация длинных списков задач, изменение формата хранения состояния в SQLite.
