# Roadmap: остатки живого прогона быстрого изменения

Дата: 8 ноября 2026 года.

Статус: прогон небольшого изменения с вопросом исполнителя, обсуждением и
центром внимания прошёл до приёмки. Найденные дефекты исправлены; ниже — то,
что оставлено на потом. Каждый пункт — отдельная задача со своей приёмкой.

## 1. Попытка с вопросом не расходует лимит попыток

Движок засчитывает остановку `needs-input` в `maxAttempts`: после ответа на
последней попытке `input_apply` требует `reset`. Нужна правка движка:
остановка вопросом возвращает счётчик попытки, не трогая счётчик нейтральных
сбоев. Критерий: тест движка — вопрос на последней попытке, ответ, применение
без `reset`.

## 2. Решения исполнителя видны оператору

Допущения, которые исполнитель принял сам ниже порога, не видны ни в карточке
быстрого изменения, ни в карточке задачи. Нужно показать их оператору (список
вопрос — выбор — обоснование — серьёзность) рядом с результатом попытки.
Критерий: e2e — принятая попытка с допущениями показывает их в карточке задачи.

## 3. Следующий этап после принятой доски

`task_create` на принятой доске советует корректировку, хотя START называет
`import-plan`; задачи `plan_import` не получают привязку `preparation`; вид
быстрого изменения показывает только первую задачу. Нужно согласовать
подсказку, привязку и вид. Критерий: тест на каждое.

## 4. Мелочи эксплуатации

- START: перед коммитом обновлённого контекста перемотать основную ветку к
  `devcontour/accepted`. Выполнено: шаг `merge --ff-only devcontour/accepted`
  перед коммитом правок, `context-lock` и `base-update`; тест
  `tests/start-context-commit.test.ts`.
- Команда остановки сервера workspace. Выполнено: `stop --workspace` по
  записи `.devcontour-local/server.json`; сигнал — только серверу, который
  подтвердил pid и экземпляр через `GET /api/server`; описано в `docs/cli.md`,
  тест `tests/server-stop.test.ts`.
- `doctor` не сообщает `budgets:applied` после одного `context-lock`.
  Выполнено: ложное «не применено» — doctor сравнивал файл целиком. Сервер
  запоминает digest ключей применённой конфигурации; `budgets:applied` —
  только при отличии `budgets`/`prices`, иначе `config:applied` с ключами;
  тест `tests/budget-doctor.test.ts`.
- `usage_report` в embedded без `repositoryId` показывает все вызовы
  workspace, включая ревью ответа. Выполнено: без `repositoryId` — общий
  контур, в embedded вместе с единственным компонентом (итог одним запросом);
  ответ называет `scope.owners`, запись — `owner`; описано в `docs/metrics.md`,
  тест `tests/usage.test.ts`.
- `session-handoff --board` для невыпущенной доски.
- Очередь в панели показывает задачу с открытым вопросом значком сбоя.
