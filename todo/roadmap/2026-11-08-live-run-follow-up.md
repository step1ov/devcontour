# Roadmap: остатки живого прогона быстрого изменения

Дата: 8 ноября 2026 года.

Статус: прогон небольшого изменения с вопросом исполнителя, обсуждением и
центром внимания прошёл до приёмки. Найденные дефекты исправлены; ниже — то,
что оставлено на потом. Каждый пункт — отдельная задача со своей приёмкой.

## 1. Попытка с вопросом не расходует лимит попыток — выполнено

Движок 0.1.0-alpha.38: остановка `needs-input` возвращает попытку в
`maxAttempts`, не трогая счётчик нейтральных сбоев; ответ на вопрос последней
попытки применяется `input_apply` без `reset` (описано в `START.md`,
`docs/agent-interface.md` и `docs/upgrade.md`). Тесты — тест движка «вопрос на
последней попытке» и `tests/input-flow.test.ts`.

## 2. Решения исполнителя видны оператору — выполнено

Блок «Решения исполнителя» (вопрос — выбор — обоснование — серьёзность, с
минимумами, которые её подняли) — у попытки в «Ходе попыток» карточки задачи и
в результате быстрого изменения. Данные — `assumptions` попытки в деталях
задачи, попытке и результате быстрого изменения (`src/application/assumptions.ts`,
описано в `docs/agent-interface.md` и `docs/ui-tour.md`). Учебный исполнитель
записывает развилки для задачи с маркером `[demo:assume]`. Тесты —
`tests/assumptions.test.ts` и `e2e/writer-decisions.spec.ts` (принятая попытка
показывает решения в карточке задачи, попытка без решений — без блока).

## 3. Следующий этап после принятой доски

Статус: выполнено. Отказ `task_create` на принятой доске называет следующий
этап (`plan_import` с `boardId`, CLI `import-plan --board`) и оставляет
корректировку для изменения принятого результата; описания операций в
каталоге говорят то же. Задачи `plan_import` привязываются к активному
изменению так же, как задачи `task_create` (привязка была, теперь закреплена
тестом и описана). Вид быстрого изменения показывает сводку всех задач
изменения со статусом и этапом, а шаги называют их число. Тесты: unit
(отказ, привязка, проекция и шаги), e2e сводки в `quick-route.spec.ts`.

`task_create` на принятой доске советует корректировку, хотя START называет
`import-plan`; задачи `plan_import` не получают привязку `preparation`; вид
быстрого изменения показывает только первую задачу. Нужно согласовать
подсказку, привязку и вид. Критерий: тест на каждое.

## 4. Мелочи эксплуатации

- START: перед коммитом обновлённого контекста перемотать основную ветку к
  `devcontour/accepted`.
- Команда остановки сервера workspace.
- `doctor` не сообщает `budgets:applied` после одного `context-lock`.
- `usage_report` в embedded без `repositoryId` показывает все вызовы
  workspace, включая ревью ответа.
- `session-handoff --board` для невыпущенной доски.
- Очередь в панели показывает задачу с открытым вопросом значком сбоя.
