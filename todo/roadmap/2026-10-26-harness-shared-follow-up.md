# Roadmap: остатки после перехода на общий harness 0.1.0-alpha.11

Дата: 26 октября 2026 года.

Статус: перенос общих алгоритмов в harness завершён. DevContour использует
`devcontour-harness@0.1.0-alpha.13` (setup, diagnostics, planning, catalog и
ограничение ответов, resolver профилей); прежние копии этих алгоритмов
удалены, продуктовые правила, память, UI и хранилище остаются в DevContour.
Ниже — то, что осталось вне этого переноса. Каждый пункт — отдельная задача
со своей приёмкой.

## 1. Токены в `/api/state`

`/api/state` — локальный эндпоинт панели за проверкой Host/Origin. Он не входил
в ограничения ответов агентских операций (diagnostics, capabilities, context),
поэтому runtime-токены и длинные значения в нём не проверялись по тем же
правилам. Нужно решить, какие поля состояния панели содержат секреты или
токены, и убрать или замаскировать их в ответе, не меняя внутренних данных
панели и не ослабляя проверку Host/Origin. Критерий: ответ `/api/state` не
содержит runtime-токенов ни в одном сценарии панели; регрессионный тест на
каждый источник.

## 2. Форматирование `tests/agent-control.test.ts`

Файл не проходит `prettier --check`; `format:check` не входит в `npm run check`,
поэтому расхождение не ловится. Отформатировать файл отдельным коммитом без
изменения логики и решить, включать ли `format:check` в `npm run check`.

## 3. Выпуск DevContour на alpha.11 — выполнено

Выпущен `0.4.0-alpha.8` с вложенным `devcontour-harness@0.1.0-alpha.13`
(общие алгоритмы alpha.11, формат состояния alpha.12 и alpha.13 не менялся).
Release notes — в `docs/upgrade.md`: отказ на путь JUnit с концом строки,
тексты отказов resolver профилей, чтение ранних форм продолжения из
состояния 0.3.x, открытие тихой базы WAL проверкой данных как неизменяемой.

## 4. Профили с `toolchain`

DevContour отклоняет профиль с `toolchain`: требования к версиям инструментов
исполняет только harness. Если продукту понадобится этот раздел, его исполнение
берётся из harness, а не пишется заново.

## 5. Команда состояния только для чтения

Каждая команда, показывающая состояние (`export`, `journal`, `queue`,
`contract-impact` и другие команды статуса), открывает базу для записи;
полный `doctor` с 0.4.0-alpha.9 читает базы только для чтения. Посмотреть очередь и доски
остановленного workspace, ничего не записав, нельзя: даже чтение меняет файлы
базы или журнала. Нужна команда только для чтения, которая показывает паузу
очереди, активные попытки, доски и статусы задач. Критерий: команда выводит
эти сведения, а листинг каталога workspace (включая `-wal`/`-shm`/`-journal`)
и отпечаток каждой базы до и после запуска совпадают; регрессионный тест в
топологиях central и component.

## 6. Лексер замыкания импортов: JSX и написание `underTest`

- В тексте JSX символы `//` после `>` лексер принимает за начало
  комментария, и импорт на той же строке выпадает из замыкания (например,
  `<p>см. http://example.test</p>; import { tally } from './tally.js'` в
  одной строке). Критерий: импорт после текста JSX с `//` попадает в
  замыкание или предложение отклоняется; регрессионный тест на `.tsx` и
  `.jsx`.
- Отказ лексера для `.tsx`/`.jsx` (например, из-за апострофа в тексте
  `<p>Don't panic</p>`) называет обходные пути: `{"Don't"}` или `&apos;`.
  Критерий: текст отказа для файлов JSX содержит оба варианта; тест на
  текст отказа.
- `underTest`, записанный как `widget.js`, не освобождает исходник
  `widget.ts`, который импортируется как `./widget.js`. Критерий: отказ
  закрепления называет написание пути, которое его снимет (`widget.ts`);
  тест на пару `.js`/`.ts`.

## 7. Эталонные наборы: число записей и расположение файлов

- Сверять объявленные доли gates (`sets[]`, их `minCases` и минимумы семейств) с фактическим числом
  записей в файле набора. Способ подсчёта зависит от формата файла (строки
  JSONL, элементы массива JSON и т. п.). Критерий: набор, где записей
  меньше `minCases` или доли не сходятся с числом записей, отклоняется до
  gates с названием набора и обоих чисел; тест на каждый поддержанный
  формат и отказ для неизвестного формата.
- Хранить файлы наборов вне worktree попытки, как корпус, чтобы реализация
  не могла прочитать ожидаемые ответы. Сейчас отклоняется только кандидат,
  который называет файл набора строковым литералом. Критерий: в worktree
  попытки нет файлов наборов, а gate получает их путь извне; тест, где
  реализация ищет файл набора обходом каталога и не находит его.

## 8. Генераторы эталонных наборов: независимая проверка выполнимости

Ответы о выполнимости (решение существует, массовая выполнимость), которые
генератор набора получает от решателя, опираются на его presolve без
независимого доказательства. Критерий: в разделе эталонных наборов
`docs/check-contracts.md` описан шаблон независимой проверки — повторное
решение без presolve (или другим решателем) с записью расхождений, — и
пример договора проверки показывает, как закрепить её журнал.
