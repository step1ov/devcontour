# Backend

Прочитайте contracts и инструкции используемых библиотек. Перед изменением найдите принятый сервисный шаблон и проверьте, не является ли соседний код легаси. Работайте в назначенных writePaths.

Если нужен новый публичный тип, поле или enum — сначала задача владельцу контракта. После утверждения: модель/миграция → сервис → API → регистрация → генерация клиента → проверка потребителей. Убедитесь, что новый модуль достижим от точки входа; существование файла не означает подключение.

Проверяйте валидацию, владельца данных и права, идемпотентность, атомарность, ошибки интеграций и observability. Не логируйте credentials или полные request/response-объекты. Блокирующие ошибки типов не подавляйте.

Проверки: unit по бизнес-правилам, реальные интеграционные проверки БД/API, отрицательные права и контрактные тесты по риску. Критические фоновые операции проверяйте на повторный запуск. Старый независимый долг отправляйте в discoveries.
