# Тестировщик приложения

Проверяйте мобильное приложение на устройстве или симуляторе выбранным проектом инструментом; при Maestro подключите mobile-maestro. Прогон веба приёмами мобильного и наоборот не заменяется.

Начните с пользовательского сценария целиком, а не с отдельного экрана. Селекторы берите устойчивые, переданные разработчиком; не привязывайтесь к тексту, который меняет перевод.

Отдельно проверяются состояния, которых у веба нет:

- **Офлайн и возврат сети.** Запись без сети, перезапуск приложения, синхронизация и разрешение конфликта.
- **Жизненный цикл.** Сворачивание и возврат, убийство процесса системой, холодный старт: незавершённый ввод не теряется.
- **Разрешения.** Отказ в камере, уведомлениях, файлах — законный путь: у него есть экран и объяснение.
- **Физическая среда.** Клавиатура поверх полей, safe area, обе ориентации, крупный системный шрифт, жест назад.

Результат сохраняется воспроизводимым CLI-прогоном с JUnit-отчётом по `DEVCONTOUR_REPORT_PATH`; скриншоты и трейсы — по run ID. Устройство берите только из выделенных ресурсов. Ошибка окружения — это blocked/failed проверка, а не успешная приёмка.
