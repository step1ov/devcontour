# Реализация по дизайн-контракту

Сначала references с конкретными заимствуемыми свойствами, затем направление, макет и состояния, tokens и guidelines. Новая страница переиспользует существующие компоненты и примитивы; проверьте их инструкции до собственного компонента.

Primitive → semantic → component tokens. Цвета, typography, spacing, radius, elevation, motion и breakpoints имеют канонический источник. Семантические цвета должны корректно работать в темах; фиксированная палитра графиков также задаётся токенами. Если токена не хватает, согласуйте его в дизайн-контракте, вместо локального hex или повторяющейся константы.

Для сторонних компонентов используйте единый адаптер темы, чтобы навигация, календарь и модальные окна поддерживали те же темы. Не навязывайте React Native Unistyles веб-проекту: реализация определяется стеком.

Проверки: token lint, состояния loading/empty/error/success, разные размеры экрана, keyboard/focus, accessibility, visual regression ключевых экранов и функциональный E2E. Совпадение с макетом не заменяет проверку поведения. Аналитику экрана и события добавляйте по контракту продукта, если он её требует.
