# Проверки и воспроизводимость

До реализации опишите наблюдаемый результат, отрицательные сценарии, права и риски. После правки определяйте область по реальному Git diff, включая удаления и переименования. Общая библиотека требует проверки потребителей, даже если их исходники не менялись.

Gates задают command как argv, cwd относительно worktree, dependsOn и при необходимости resources. Используйте конечные CI-команды без watch и автоисправления; линтер не должен менять проверяемый SHA. Кодоген и сборка prerequisites идут до проверок типов, затем реальные тесты с JUnit. Typecheck/build не доказывают бизнес-поведение.

Тест создаёт изолированные данные с DEVCONTOUR_RUN_ID. Проверяйте результат действия, а не только успешное нажатие; ожидайте состояние с ограниченным timeout. Не маскируйте баг retries, паузами или optional assertion. Cleanup должен выполняться и при падении, а не только в конце успешного сценария. После аварии удаляйте только данные текущего прогона.

Ведущий агент поднимает окружение и проверяет readiness. Пользователь не обязан вручную запускать backend перед каждым прогоном. Скрипт должен владеть своими дочерними процессами, завершать их при exit/TERM и сохранять исходный код ошибки, даже если генерация отчёта завершилась успешно. Значения секретов в отчёт не попадают.

MCP помогает исследовать приложение и отладить сценарий; результат сохраняется в воспроизводимом CLI-тесте. DEVCONTOUR_REPORT_PATH — абсолютный путь JUnit; скриншоты/трейсы сохраняйте по run ID. PASS требует выполненных testcase без failures и skips. Ошибка окружения означает blocked/failed проверку, а не успешную приёмку.

DEVCONTOUR_RESOURCES_JSON содержит зарезервированные устройства, порты и имена тестовых аккаунтов. Один физический ресурс должен иметь одинаковые kind/value во всех workspace. Пользуйтесь только выделенными ресурсами и не запускайте независимый драйвер к занятому устройству.
