# Контракты

Для API: схема, коды ошибок, auth, pagination, idempotency, совместимость.
Для событий: schema/version, ordering, retries, delivery semantics, дедупликация.
Для UI: состояния, validation, navigation, semantic tokens и версия макета.

Утверждение в DevContour фиксирует текст и digest. Новая семантика — новый contract ID и новая ревизия задач. Поправки этапов не копите в тексте: когда документ разросся (от 75 % предела в 60 000 знаков) или набрал шесть поправок, перепишите его в описание текущего поведения без изменения смысла и проведите `contract-change --consolidate`. Консолидация сохраняет ID правил, заголовки, на которые ссылаются другие контракты, артефакты и checks; привязанные задачи её не замечают. Если правила не помещаются и после неё — файл-продолжение. Frontend может работать по согласованному mock, но итоговая приёмка требует интеграции с настоящим backend.
