# Проверка инженерных расширений

Дата: 2026-09-17. Node 24.3.0. Изменения подготовлены и проверены в изолированной рабочей копии, затем перенесены в установленный devcontour-template с проверкой исходных хешей файлов.

## Результаты

- `npm run check`: token lint, TypeScript/Vite build и 55 unit/integration тестов прошли, 0 failed, 0 skipped на этом этапе. Полный check завершился неуспешно на запуске Chromium для трёх браузерных E2E.
- После последнего изменения CLI (запрет context-lock при работающей очереди) выполнены typecheck и отдельный интеграционный тест CLI: 1 passed. Итого 56 разных unit/integration сценариев проверены; общий прогон до этого изменения содержал 55.
- `npm run format:check`: PASS. Изменённый workflow проверен реальным Git, несколькими репозиториями и отдельными процессами, без вызовов моделей.
- HTTP E2E: 1 passed. Browser E2E: 3 не смогли запустить Chromium из-за `bootstrap_check_in ... MachPortRendezvousServer: Permission denied (1100)` в среде macOS. Это ограничение запуска, а не PASS приложения. Полный E2E требуется повторить в окружении, где Chromium запускается.
- Chrome DevTools MCP: отдельный UI smoke на временном fixture. Доска «Находки агентов» отображается, находка видна в графе и списке со статусом «Черновик», источник path:line и SHA доступны в карточке, критерии воспроизведения присутствуют, до утверждения запуск очереди недоступен. Ошибок console.error нет. Это не замена трём автоматическим E2E и не полный accessibility-аудит.

## Новое покрытие

- Gate DAG: правильный порядок prerequisites, циклы и неизвестные зависимости.
- Component DAG: валидация циклов и неизвестных репозиториев.
- Контекст: выбор по роли/явным IDs, закрепление обычных Git-файлов, независимость от незакоммиченных изменений, обнаружение несовпадения digest, отказ без закрепления, передача исполнителю и ревьюеру, сохранение receipt/артефакта.
- CLI context-lock/context-show: закрепление committed-инструкций, чтение контекста задачи, запрет изменения при неприостановленной очереди.
- Write scope и generatedPaths: нарушение останавливает интеграцию.
- Findings: автоматическое создание непроверенных draft-задач, происхождение, дедупликация и fencing отменённой попытки.
- Кодоген: реальная команда в отдельном cwd до теста потребителя на candidate и integration SHA; ресурс передаётся через DEVCONTOUR_RESOURCES_JSON.
- Ресурсы: исключительное владение между процессами с разными локальными IDs, атомарность набора, отсутствие перехвата по TTL, проверка token/PID, отмена ожидания и освобождение после ошибки.
- Consumer impact: принятая baseline всех продуктов, изменение manifest библиотеки запускает проверки её потребителя, prerequisites выполняются до E2E, независимый продукт исключается только в affected-режиме. Несовместимое значение библиотеки отклоняется неизменённым продуктовым тестом. Неполный граф возвращает полную проверку.
- Прежние сценарии DAG, leases, fencing, immutable revisions, multi-repo acceptance, journal и workspace isolation сохранили прохождение.

## Ограничения

Живые Codex/Claude CLI, Maestro на реальном устройстве, мобильная сборка и авторизация приложения не запускались: для этого нужен конкретный продукт и настроенные инструменты. MCP инструкции не выдаются за такую проверку. Resource pool координирует DevContour-процессы на одном хосте и не создаёт ресурсы/контейнеры. Порядок работы и границы описаны в [инженерных расширениях](engineering-context.md).
