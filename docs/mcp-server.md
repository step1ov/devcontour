# MCP и переносимый skill DevContour

MCP даёт модели типизированные операции DevContour. Skill объясняет, когда ими пользоваться и как довести продукт до приёмки. CLI остаётся доступен для bootstrap, независимого ревью и длительных проверок. Это разные интерфейсы одного процесса разработки.

## Подключение

Установите [пакет](distribution.md). В MCP-клиенте добавьте stdio-сервер с абсолютным путём к исполняемому файлу и workspace. Типичный JSON-формат клиента:

```json
{
  "mcpServers": {
    "devcontour-shop": {
      "command": "/absolute/tools/node_modules/.bin/devcontour",
      "args": ["mcp", "--workspace", "/absolute/shop-workspace"]
    }
  }
}
```

Конкретное место настройки зависит от клиента. Рабочий каталог процесса не влияет на выбор проекта. Для CRM создаётся отдельная запись со своим workspace. MCP не хранит глобальный «текущий проект» и не позволяет подменить путь аргументом отдельного tool call. При подключении первым запросом прочитайте `project_context` и сравните workspace с поручением.

MCP использует официальный TypeScript SDK 2.0.0 и stdio. В stdout передаются только сообщения протокола; диагностические ошибки идут в stderr. Встроенного сетевого MCP endpoint и удалённой аутентификации в этой версии нет. Веб-консоль и MCP можно запускать независимо: они работают с одной SQLite через существующие транзакции, но только scheduler консоли/команды `run` выдаёт работу. Подключение, чтение и отключение MCP не запускают модели и не останавливают чужой runner.

## Возможности и ограничения

`devcontour capabilities` и `GET /api/capabilities` возвращают версию приложения, `protocolVersion`, лимиты и JSON Schema каждой операции. MCP `tools/list` строится из того же каталога. Клиенту не нужно угадывать команды из устаревшего текста.

Помимо [контекстных запросов и checkpoints](agent-interface.md), доступны:

| Операция                                                               | Результат                                                                                      |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `plan_import`                                                          | Черновая доска и DAG; цикл или неизвестная зависимость отклоняются атомарно                    |
| `board_create`, `task_create`                                          | Новая доска или черновая задача с проверкой владельца                                          |
| `task_edit`                                                            | Правка черновика при совпадении `expectedDigest` из briefing                                   |
| `task_assign`                                                          | Назначение участнику команды                                                                   |
| `task_retry`                                                           | Явная повторная попытка в рамках лимита после диагностики                                      |
| `board_correct`                                                        | Новая ревизия принятой доски с пересчётом затронутых задач                                     |
| `changeset_create`                                                     | Общая работа по нескольким доскам без автоматической приёмки                                   |
| `queue_set`                                                            | Пауза или возобновление выдачи; возобновление может запустить модели на уже работающем сервере |
| `requirements_snapshot`, `requirements_report`, `requirements_correct` | Разделы ТЗ, актуальность покрытия и корректировка                                              |
| `workflow_start`, `workflow_status`, `workflow_retry`                  | Сохраняемое продолжение подготовленной доски или ChangeSet                                     |
| `workflow_metrics`                                                     | Длительности стадий, ожидание и результаты всех попыток                                        |
| `signal_ingest`, `signal_status`                                       | Дедупликация внешних наблюдений и локальные drafts                                             |

Приёмка, независимое ревью и длительная общая проверка вызываются существующими командами runner. Их нельзя заменить переданным моделью `approved: true` или `passed: true`. MCP не открывает операторские HTTP-действия подтверждения от имени агента. Для автоматического продолжения есть `workflow_start`: он регистрирует сохраняемый job, а работающий сервер выполняет долгие стадии. `workflow_status` возвращает состояние. При необходимости ведущий агент по-прежнему может запускать отдельные CLI-команды. Договор восстановления — [workflow](lead-workflow.md).

После обрыва связи сначала прочитайте состояние: обычное создание доски/задачи может дать дубликат при повторе. `workflow_start` дедуплицирует вход по digest, `signal_ingest` — по source/event ID и содержимому. Read-only и idempotency annotations описывают свойства для клиента. Ошибки возвращаются как `isError`; конфликт требует перечитать актуальное состояние. Лимит входа — 100000 байт, результата — 64 KiB. Контекстные операции имеют pagination; для больших отчётов требований и метрик используйте соответствующую native CLI-команду. После ошибки размера у mutation проверьте состояние до повтора: само действие могло завершиться.

Все входы проходят общие Zod-схемы и доменные проверки `AgentService`; CLI `agent`, HTTP `/api/agent` и MCP используют этот же слой. Изменение транспорта не меняет fencing, независимость reviewer, владение компонентом и доказательства на SHA.

## Skill

`devcontour skill-path` печатает каталог `skills/devcontour` установленного пакета. Его можно скопировать в каталог skills выбранного клиента. DevContour не изменяет глобальные настройки агента автоматически: место установки и способ обнаружения принадлежат клиенту.

`SKILL.md` содержит компактный маршрут: выбор workspace, bootstrap из ТЗ, контракты, DAG, независимое ревью, очередь, диагностика и продолжение с checkpoint. Подробные схемы вынесены в `references/agent-api.json`. Сборка генерирует справочник из реального каталога команд; `npm run check:skill` проверяет совпадение. Обновляйте skill вместе с пакетом, а при сомнении читайте live `capabilities`.

Skill не даёт дополнительных прав на публикацию или изменение сторонних проектов и не заменяет правила продукта. Продуктовые правила остаются в своём репозитории. Новая сессия использует документы, текущее состояние и checkpoint; наличие skill само по себе не делает ведущего агента постоянно работающим сервисом.
