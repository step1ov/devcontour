## Что проверяют новые сценарии

1. Новая локальная БД восстанавливает задачи из Git; тела задач и baseline остаются в компоненте.
2. Два clone добавляют независимые задачи в одну доску; правки разных полей объединяются.
3. Противоречивое изменение требует адресного решения; ошибка не меняет БД и Git-файлы.
4. Завершение переносится с committed receipt и доступными Git SHA; активные Run/token/lease не восстанавливаются.
5. Повреждённые receipts, отсутствующие коммиты, циклы, удаление истории и голый `done` отклоняются.
6. Назначение фильтрует claim; sync отклоняет активную работу, неявный checkout и symlinks.
7. Настоящий runner выполняет gates и обе фазы интеграции, после чего результат переносится в другой clone.
8. Общий граф ссылается на задачи продукта и библиотеки без копирования их тел в Git и baseline workspace.
9. Изначально пустая общая доска сохраняет физического владельца после добавления задач.
10. Незавершённый настоящий Git merge conflict блокирует импорт.
11. CLI `sync`, `sync-status` и `assign-task` работают с явно выбранным workspace.

Первый общий прогон обнаружил старое ограничение журнала на числовые ChangeSet IDs. После исправления UUID поддерживаются журналом; повторный общий прогон дал 79 PASS.

## Проверка интерфейса

Для браузера создан отдельный fixture: Alice выполняет задачу через demo writer/reviewer с настоящим JUnit gate, интегрирует результат и сохраняет task receipt. Bob получает отдельные clones продукта и workspace и выполняет `sync`. Его БД не содержит локального Run этой задачи.

Карточка и граф показывают «Принята из Git», ответственного `alice`, источник Git и четыре проверки candidate/integration. Счётчик попыток равен нулю. Утверждение «проверена локально» для этого результата отсутствует. До аудита в консоли приложения не было ошибок/предупреждений; мобильный аудит также завершился без них.

Сохранены [desktop](images/team-sync.png) и [mobile](images/team-sync-mobile.png). Это реальные изображения учебного приложения; DOM не подменялся. Axe временно загружался как локальный тестовый asset и удалён после проверки.

## Границы результата

Receipt является свидетельством доверенного Git-репозитория, а не цифровой подписью и не проверкой отсутствующего лога по его хешу. Этот прогон не проверяет распределённые leases, публикацию, корпоративную авторизацию или перенос всей среды. Общие Verification/Delivery/acceptance, host resources и незавершённые процессы остаются локальными. Договор использования — [team-sync.md](team-sync.md).
