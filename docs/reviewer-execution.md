# Что подтверждает независимое ревью

Ревью и тестовый gate — разные проверки. Положительный ответ модели не заменяет выполненные тесты. Отсутствие команд у reviewer также должно быть видно, даже если обязательные gates отдельно прошли.

## Формат и совместимость

Новые ответы CLI reviewer обязаны содержать `execution`: массив `commands` с `command`, `exitCode`, `summary` и `noCommandsReason` (строка при пустом массиве, иначе null). Это самоотчёт модели, поэтому он сохраняется отдельно от наблюдений runtime.

Находка ревью задачи может нести `reproduction`: свойство (testId или критерий), точный вход как JSON-текст, ожидаемое и фактическое, команду (argv) и признак `executed`. Контур записывает такие находки в реестр воспроизведений задачи: одно свойство на одном входе — одна запись, повторы добавляют прогон. `claimed` — ревьюер утверждает, что запускал команду; `observed` — запуск той же команды подтверждён журналом проверок `run_check`, а не словами модели. Команда из текста находки контуром не исполняется, вход и ответы проходят redaction. Следующая попытка исполнителя получает реестр в подсказке, ведущий — в `task_briefing` (раздел `reproduction`). Это диагностика: обязательным gate воспроизведение становится только как тест в новой ревизии договора проверки через ревью контракта.

Runner добавляет в локальное review evidence поле `inspection`: `mode` (`commands` или `diff-only`), источник наблюдения, реально зарегистрированные CLI команды и причину отсутствия команд. Для Codex источником служат события `item.completed` типа `command_execution`, а не финальный текст модели. Неуспешная инициализация sandbox не доказывает выполнение команды. `commands` означает наличие завершённой команды с exit 0; это ещё не доказательство запуска достаточных тестов. `diff-only` означает отсутствие подтверждённых успешных команд и не исключает чтение файлов встроенными инструментами.

Существующие записи SQLite и Git receipts не переписываются, их digest сохраняется. Поле необязательно при чтении истории: отсутствие означает «исполнение команд не зафиксировано», а не commands. Новые локальные записи получают классификацию. В переносимом receipt остаётся digest review; подробности локального процесса в Git не экспортируются. Изменение не отменяет обязательные candidate/integration gates и не переоценивает старую приёмку задним числом.

Проверка приёмки также сравнивает tracked и untracked-состояние worktree до и после reviewer. Незапрошенный новый файл блокирует интеграцию. Это обнаружение изменения, а не системный запрет записи; игнорируемые временные файлы и внешние ресурсы требуют отдельной изоляции.

## Ограничения прав

Codex получает профиль прав DevContour и `approval_policy="never"`: чтение и исполнение разрешённых команд, запись только во временный каталог, каталоги контура и учётных данных закрыты, сети нет (см. «Изоляция исполнителя, ревьюера и проверок» в configuration.md). Флаг `--sandbox` не передаётся: с ним codex игнорирует профиль прав. Тесты, которым нужны build/cache/report файлы в worktree, в таком режиме могут не работать: их исполняет отдельный gate. Нельзя снимать ограничения ради успешного ревью.

Claude reviewer по умолчанию получает только Read/Glob/Grep. Bash он получает, только если профиль инструментов явно включил его в `claudeTools`; тогда shell исполняется в песочнице ОС без сети и без записи в проверяемый каталог, а при недоступности песочницы запуск отказывает. Edit, Write и NotebookEdit запрещены всегда. Для встроенных файловых инструментов это ограничение правил прав, не независимый файловый sandbox. Подключаемые MCP должны сами обеспечивать права чтения; список инструментов не превращает сервер с правами записи в read-only.

## Проверки ревьюера под пределами контура

Ревьюер, который может запускать команды (Bash в профиле claude; shell codex), получает инструмент `run_check` от DevContour. Команда (argv, без shell) исполняется тем же исполнителем, что и гейты: в песочнице ОС, с исходниками только для чтения, временными файлами в своём `TMPDIR` и уборкой потомков. Срок задаёт контур, а не модель: предел одной команды, общий бюджет проверок ревью и резерв на заключение берутся из `reviewProbes` и ограничены `runTimeoutMs`. Превышение — типизированный результат с командой, длительностью, пределом и частичным выводом, а не зависание ревью; исчерпанный бюджет означает, что команда не запускалась. Таймаут — наблюдение о команде на данном входе, а не доказанный дефект. Сроки вызова инструмента в CLI (`tool_timeout_sec` у codex, `MCP_TOOL_TIMEOUT` у claude) выставлены выше предела контура, и собственный Bash ревьюера claude ограничен тем же пределом команды. Значения переменных окружения CLI передаёт серверу по имени; на диск они не пишутся.

Каждый запуск записывается журналом контура (`probes.jsonl` в каталоге ревью), и review evidence содержит список проверок по этому журналу, а не по самоотчёту модели. Ревьюеру, который только читает, инструмент не выдаётся: он ограничивает срок, а не расширяет права. Собственный shell codex-ревьюера остаётся альтернативным путём, и на него предел контура не распространяется; гарантия относится к командам через `run_check`.

Копия worktree сама по себе не изолирует ревьюера от исходного репозитория по абсолютному пути. Для произвольных тестовых команд обоих runtime нужна отдельно проверенная контейнерная среда с read-only исходниками и Git metadata, writable scratch/cache и без доступа к оригинальному checkout. Такая среда пока не реализована. Не выдавайте fixture проверки аргументов или отказ при изменении Git за доказательство OS-изоляции живого CLI.

## Проверка среды без вызова модели

`node scripts/reviewer-sandbox-probe.mjs` создаёт временный Git fixture и через штатный `codex sandbox` проверяет чтение, тест без файлового вывода и отказ записи в файл и refs. Проверка не вызывает модель, не читает credentials и не ослабляет sandbox. Если sandbox не запускается, результат — ограничение среды, не PASS из-за того, что запись тоже не состоялась. Сначала должен успешно выполниться тест чтения.

В текущей сессии уже `codex sandbox macos --help` завершился с `sandbox-exec: sandbox_apply: Operation not permitted`. Это воспроизводит запрет вложенного sandbox до запроса модели; изменение прав служебной SQLite само по себе эту причину не устраняет.

Официальные договоры CLI: [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [Claude CLI reference](https://code.claude.com/docs/en/cli-reference). Фактические ограничения конкретного хоста проверяет probe и последующий явно разрешённый пилот.
