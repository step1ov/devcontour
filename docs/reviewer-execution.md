# Что подтверждает независимое ревью

Ревью и тестовый gate — разные проверки. Положительный ответ модели не заменяет выполненные тесты. Отсутствие команд у reviewer также должно быть видно, даже если обязательные gates отдельно прошли.

## Формат и совместимость

Новые ответы CLI reviewer обязаны содержать `execution`: массив `commands` с `command`, `exitCode`, `summary` и `noCommandsReason` (строка при пустом массиве, иначе null). Это самоотчёт модели, поэтому он сохраняется отдельно от наблюдений runtime.

Runner добавляет в локальное review evidence поле `inspection`: `mode` (`commands` или `diff-only`), источник наблюдения, реально зарегистрированные CLI команды и причину отсутствия команд. Для Codex источником служат события `item.completed` типа `command_execution`, а не финальный текст модели. Неуспешная инициализация sandbox не доказывает выполнение команды. `commands` означает наличие завершённой команды с exit 0; это ещё не доказательство запуска достаточных тестов. `diff-only` означает отсутствие подтверждённых успешных команд и не исключает чтение файлов встроенными инструментами.

Существующие записи SQLite и Git receipts не переписываются, их digest сохраняется. Поле необязательно при чтении истории: отсутствие означает «исполнение команд не зафиксировано», а не commands. Новые локальные записи получают классификацию. В переносимом receipt остаётся digest review; подробности локального процесса в Git не экспортируются. Изменение не отменяет обязательные candidate/integration gates и не переоценивает старую приёмку задним числом.

Проверка приёмки также сравнивает tracked и untracked-состояние worktree до и после reviewer. Незапрошенный новый файл блокирует интеграцию. Это обнаружение изменения, а не системный запрет записи; игнорируемые временные файлы и внешние ресурсы требуют отдельной изоляции.

## Ограничения прав

Codex получает `--sandbox read-only` и `approval_policy="never"`. Read-only разрешает чтение и исполнение разрешённых команд, но не запись в worktree и Git metadata. Тесты, которым нужны build/cache/report файлы, могут не работать в таком режиме: их исполняет отдельный gate. Нельзя заменять режим на unrestricted ради успешного ревью.

Claude reviewer получает только Read/Glob/Grep; Bash, Edit, Write и NotebookEdit явно запрещены. Произвольный shell не добавляется: разрешение Bash без системной изоляции дало бы возможность писать через shell. Это ограничение инструментов, не независимый файловый sandbox. Подключаемые MCP должны сами обеспечивать права чтения; список инструментов не превращает сервер с правами записи в read-only.

Копия worktree сама по себе не изолирует ревьюера от исходного репозитория по абсолютному пути. Для произвольных тестовых команд обоих runtime нужна отдельно проверенная контейнерная среда с read-only исходниками и Git metadata, writable scratch/cache и без доступа к оригинальному checkout. Такая среда пока не реализована. Не выдавайте fixture проверки аргументов или отказ при изменении Git за доказательство OS-изоляции живого CLI.

## Проверка среды без вызова модели

`node scripts/reviewer-sandbox-probe.mjs` создаёт временный Git fixture и через штатный `codex sandbox` проверяет чтение, тест без файлового вывода и отказ записи в файл и refs. Проверка не вызывает модель, не читает credentials и не ослабляет sandbox. Если sandbox не запускается, результат — ограничение среды, не PASS из-за того, что запись тоже не состоялась. Сначала должен успешно выполниться тест чтения.

В текущей сессии уже `codex sandbox macos --help` завершился с `sandbox-exec: sandbox_apply: Operation not permitted`. Это воспроизводит запрет вложенного sandbox до запроса модели; изменение прав служебной SQLite само по себе эту причину не устраняет.

Официальные договоры CLI: [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [Claude CLI reference](https://code.claude.com/docs/en/cli-reference). Фактические ограничения конкретного хоста проверяет probe и последующий явно разрешённый пилот.
