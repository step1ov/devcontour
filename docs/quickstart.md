# Быстрый старт

Цель первого запуска — увидеть путь одной задачи от плана до доказанного результата. Demo позволяет изучить систему без настройки моделей, корпоративных доступов и продуктовой инфраструктуры.

## 1. Подготовить установку

Нужны Node.js 24.3+ с `node:sqlite`, npm и Git. Установка зависимостей требует доступа к используемому npm registry. Проверка браузером дополнительно требует Chromium для Playwright; для запуска самой консоли это не нужно.

```sh
cd /absolute/devcontour
node --version
git --version
npm ci
npm run build
npm run demo
```

Если DevContour установлен в другом месте, замените путь в `cd`. `npm ci` использует lockfile. Не обновляйте одновременно эту же установку из нескольких агентских сессий.

Ожидаемый результат: сервер сообщает URL `http://127.0.0.1:4317` и учебный режим. Данные demo сохраняются между запусками в `.harness/demo/`; повторный запуск продолжает тот же пример. Для отдельного учебного экземпляра:

```sh
npm run devcontour -- demo --data /tmp/devcontour-learning --port 4318
```

При занятом порте выберите другой. Не останавливайте неизвестный сервер ради освобождения порта.

## 2. Пройти один цикл

1. Откройте консоль по выведенному URL. Посмотрите граф: связи показывают, какая задача должна закончиться до начала другой.
2. Откройте карточку. Сопоставьте описание, роль, критерии приёмки и контракты.
3. Нажмите «Запустить очередь». Независимые готовые задачи могут выполняться параллельно.
4. В завершённой задаче изучите попытку, candidate/integration SHA, логи gates и независимое review-fixture. `done` появляется после локальной интеграции.
5. Когда выполнен весь объём доски, примите её. Появится сохранённый снимок ревизии.
6. Создайте корректировку принятого результата, указав задачу и причину. Убедитесь, что появилась новая ревизия, а история предыдущей сохранилась.

Это настоящий цикл Git и проверок, но результаты исполнителя и ревьюера в demo детерминированы. Он демонстрирует механику, а не способности AI и не готовность ваших CLI.

Если продолжаете старый demo, его задачи уже могут быть выполнены. Изучите историю либо используйте новую папку `--data`; удалять прежние данные для начала обучения не требуется.

Наглядный разбор экранов — [обзор консоли](ui-tour.md).

## 3. Остановить и продолжить

`Ctrl+C` завершает сервер. При штатной остановке очередь ставится на паузу, текущие процессы останавливаются. Незавершённую попытку нельзя считать завершённой только потому, что процесс исчез.

Повторите ту же команду с тем же `--data` и портом. Состояние восстанавливается из SQLite; повторный импорт плана не нужен. Пауза останавливает выдачу новых работ, но сама по себе не отменяет уже выполняемые задачи.

## 4. Перейти к реальному продукту

Подготовьте:

- Каталог продукта с непустым `docs/spec.md`.
- Отдельный абсолютный путь workspace вне репозитория продукта и установки DevContour.
- Доступные ведущему агенту Codex/Claude CLI, инструменты сборки и зависимости проекта. По умолчанию исполнители используют Claude, ревьюер — Codex; обратная пара тоже поддерживается.

Дайте агенту поручение из [README](../README.md). Он выполнит подготовку по [START.md](../START.md), запустит сервер, проверит принадлежность workspace и сообщит URL. Самостоятельное знание всех команд от оператора не требуется.

Одна из команд, которую выполнит агент:

```sh
npm run devcontour -- setup --repository /absolute/product --profile react-vite-admin --workspace /absolute/product-workspace
```

`needs-agent-bootstrap` — ожидаемый промежуточный ответ. После него нужно создать или проверить каркас продукта, адаптировать правила и gates, сделать начальный Git-коммит и закрепить контекст. Setup не выполняет эти инженерные действия автоматически.

Если есть библиотеки, передайте их пути сразу: агент создаст общий реестр. Подключение одного репозитория и реестра нескольких репозиториев — разные начальные маршруты; [workspace guide](workspaces.md) описывает выбор.

## 5. Если вы разработчик DevContour

```sh
npm run dev
```

Этот режим запускает demo-сервер с Vite middleware: API и UI находятся на одном origin. Изменения интерфейса подхватываются Vite; при изменениях серверного TypeScript перезапустите процесс. Не подключайте разработческую сборку к рабочему продукту для обычного изучения системы.

Затем прочитайте [руководство разработчика](development.md) и выберите маленькое изменение с понятным наблюдаемым результатом. Начать удобно с маршрута `CLI/API → Harness → Store → Scheduler → Evidence`, описанного там.

## Проверка понимания

После первого запуска вы должны уметь показать, где находятся: постановка задачи, её отдельная попытка, причина блокировки, два проверенных SHA, приёмка доски и новая ревизия корректировки. Если неясно, почему это разные сущности, перейдите к [концепциям](concepts.md).
