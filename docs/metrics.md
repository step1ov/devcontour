# Метрики процесса

`devcontour metrics --workspace /absolute/workspace` показывает общий контур; `--repository-id main` выбирает компонент. MCP предоставляет `workflow_metrics` с тем же выбором владельца. Большой полный отчёт читайте через CLI.

Каждая локальная попытка содержит общий elapsed time, статус, runtime/model, digest политики и измеренные интервалы: реализация, candidate/integration test gates, независимое review, ожидание интеграции, setup/ready/cleanup настроенного lifecycle. Интервалы имеют IDs и события начала/окончания. При аварии незакрытый интервал помечен `incomplete`; это не успешное измерение. Некоторые подготовительные действия не инструментированы, поэтому сумма этапов не обязана равняться общему времени.

Ожидание зависимостей считается от утверждения до готовности последней зависимости. Ожидание выдачи — от готовности до claim; оно объединяет паузу, доступность workers и назначение участнику. Оно не называется временем работы модели. Старые/импортированные записи без временных границ дают `null`, а не выдуманный ноль.

Отчёт сохраняет failed/cancelled/expired попытки. Доля приёмок с первой попытки считается среди локальных задач, завершённых успешно или неуспешно; активные задачи и импортированные receipts исключены. Корректировки видны отдельно. В общем контуре также есть время ChangeSet и, для remote completion, ожидание после успешной совместной проверки до приёмки. Это ожидание не является точным временем работы человека.

Расходы пока не поступают из провайдеров: `costUsd: null`. Число строк, токенов или commits не подменяет стоимость и качество результата. Для пилота сравнивайте одинаковый набор задач, конфигурацию и число workers; сохраняйте исходный отчёт вместе с условиями эксперимента.
