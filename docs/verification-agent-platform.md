# Проверка DevContour 0.2

Дата: 17 сентября 2026. Среда: macOS, Node.js 24.3.0. Изменения проверены по этапам и сохранены отдельными коммитами. Вызовов реальных моделей, публикации npm, push, корпоративных forge/MCP и настоящих устройств в этих проверках нет.

## Реализованные этапы

1. **Контекст и продолжение.** Обзор выбранного контура, полное постраничное задание, объяснения ожидания, ограничение ответа 64 KiB, отклонение устаревших cursor и checkpoint, неизменяемые Git-файлы в репозитории владельца.
2. **Устанавливаемая поставка.** Скомпилированный CLI, сервер и UI, профили и скрытые файлы шаблона. Работа из постороннего cwd без исходников и `tsx`. Исправлена проверка workspace через альтернативный системный путь.
3. **MCP и skill.** Общий каталог схем и прикладной слой для CLI/HTTP/MCP; 14 инструментов; stdio с явной привязкой к workspace. Справочник skill генерируется из кода. Артефакты проверки и операторские подтверждения нельзя произвольно передать через MCP.
4. **Командные checkpoints.** Первые заметки в независимых клонах используют общую Git identity. Настоящий Git merge сохраняет обе заметки без конфликта. Исторические leases и тела задач не переносятся в checkpoints.
5. **Наблюдение и регрессия.** Причины ожидания в UI, корректные runtime/model для компонента и фактической попытки, новые скриншоты и документация. Проверка установленного пакета включена в `check`; CI слушает `master` и `main`. E2E fixture имеет явную Git identity и не зависит от глобальных настроек разработчика.

## Дополнительная проверка работающим браузером

Через Chrome DevTools проверен отдельный demo-сервер с настоящими локальными Git-операциями и детерминированными исполнителями:

- Карточка показывает незавершённую зависимость и паузу; после выполнения причины исчезают.
- Пять задач проходят выполнение, тесты, ревью и интеграцию; затем доска принимается.
- Корректировка контракта затрагивает пять задач и создаёт r2. После повторного выполнения r2 принимается; digest принятой r1 остаётся прежним.
- Через UI создаются отдельная доска и две задачи. Зависимость первой от второй при существующей обратной связи отклоняется с сообщением о цикле. Состояние остаётся прежним: 0 и 1 зависимость соответственно, обе задачи — draft.
- На desktop 1600×1100 и mobile 390×844 axe возвращает **0 violations**, горизонтального переполнения нет. Необработанных JavaScript-ошибок во время основного цикла нет; отрицательная проверка цикла ожидаемо возвращает ошибку API.

Сохранены [desktop](images/task-next-step.png) и [mobile](images/task-next-step-mobile.png). Подписи и назначение элементов — в [обзоре UI](ui-tour.md). Эта проверка даёт дополнительное подтверждение поведения, но не меняет результат штатного Playwright на PASS.

## Границы результата

Это рабочее локальное развитие системы, без миграции формата SQLite. Checkpoints добавляют переносимые файлы контекста. MCP предоставляет контекст и управление графом; длительное независимое ревью и общая проверка вызываются существующим CLI runner. Фоновый ведущий агент, удалённые sandboxes, распределённые leases и учёт стоимости провайдеров здесь не реализованы.

Следующий полезный этап — пилот на реальном продукте с библиотеками, его ТЗ и доступами: проверить bootstrap, контракты, настоящие тесты, права внешнего MCP и приёмку комбинации SHA. Новые runtime или удалённое исполнение следует добавлять через отдельный проверяемый адаптер. Текущая fixture-проверка не подтверждает доступность конкретной корпоративной среды.
