# Проверка после внешнего ревью

Дата: 2026-09-18. Исходная версия: `71a0b7d`. Это отчёт об изменениях и фактических проверках, а не обещание готовности к любому продукту.

## Что изменено

- Удалены персональные абсолютные пути из рабочих документов и публикуемых журналов. Исторические логи перенесены в `evidence/`, обезличивание отмечено в README каталога. История Git не переписана: старые коммиты могут содержать прежний текст.
- `.idea/` исключена из Git и сохранена локально. Добавлена выбранная владельцем лицензия MIT.
- Старое служебное имя удалено из исходников, CLI, HTTP, шаблонов, профилей и инструкций. Переносимая память — `.devcontour/`; локальное состояние — `.devcontour-local/`; конфигурация — `devcontour.component.json`. Старые алиасы, каталоги и refs не поддерживаются. Автоматической миграции нет.
- README переработан на русском: понятный пример, польза, запуск и честные ограничения. Названий конкурентов нет.
- Добавлен ESLint с анализом типов и React Hooks; проверка цветовых токенов сохранена. `@types/node` приведён к 24.13.5. TypeScript закреплён на 6.0.3: typescript-eslint 8.70.0 поддерживает версии ниже 6.1, поэтому TypeScript 7 с ним не использован. ESLint — 10.10.0.
- Исправлены обработка отклонённого Promise HTTP listener, callback таймера и зависимости React effects. Исключения с falsy-значением больше не теряются после lifecycle cleanup; регрессионный тест проверяет `undefined`, `false`, `0` и пустую строку.
- npm-пакет проверяет отсутствие `evidence/` и `.idea/`. CI сохраняет полный журнал `check` и выполняет format check, чтобы причина следующего сбоя была доступна вместе с браузерными артефактами.

## Живой пилот

ТЗ одной инженерной задачи: изменить `list()` с массива на `{items, total}`, сохранить два исходных элемента и обновить `names()`, чтобы потребитель по-прежнему возвращал `Ada,Lin`. Исполнитель может менять только `src/`; скрипт проверки и постановка защищены.

В успешном запуске использованы **Claude Code 2.1.263 / claude-opus-5** и **Codex CLI 0.154.0-alpha.6.2 / gpt-5.6-sol**. Предельные настройки: одна попытка, один worker, максимум три вызова, 240 секунд на попытку. Финансового hard cap между двумя runtime нет; цена неизвестного вызова не считается нулём.

Результат: **PASS для одной заранее утверждённой задачи**, 3 вызова, 195.416 секунды, без retry внутри успешного запуска:

1. Claude изменил реализацию и потребителя.
2. Реальный test gate проверил API и результат потребителя на candidate SHA.
3. Codex вернул структурированное независимое ревью.
4. DevContour подготовил integration SHA, повторил test gate и ревью.
5. Обе пары evidence прошли, задача получила `done`, локальная ветка обновлена.

**Ограничение ревью:** в обоих ответах Codex явно сообщил, что запуск команд в read-only sandbox недоступен. Он анализировал переданный точный diff. Поэтому результат подтверждает вызовы моделей, изменение кода, реальные gates, протокол ревью и условия приёмки. Он не подтверждает полноценное исследование reviewer всего репозитория в этой среде. Для большого кода нужен повторный пилот там, где инструменты reviewer работают. Ослаблять sandbox ради зелёного результата не стали.

Claude сообщил **$0.188831** за реализацию. Для двух вызовов Codex стоимость неизвестна; полный итог — unknown. Отдельный диагностический запрос Claude стоил $0.01981625; это не входит в стоимость успешной задачи. Неуспешные попытки также не объявляются бесплатными при отсутствии telemetry.

[Обезличенное свидетельство](../evidence/live-pilot-2026-09-18.json) содержит модели, версии CLI, затраченное время, telemetry, SHA и четыре evidence. Полные runtime logs, SQLite и временные worktree остаются локальными и не публикуются.

### Что не получилось с первого раза

Первый запуск оборвался по таймауту на Claude через 240 секунд без результата. Точную причину этого таймаута из пустого runtime log установить нельзя. Отдельная проверка Claude ответила `READY`, подтвердив доступ к модели. Первый отдельный запуск Codex остановился ещё до модели: его локальная SQLite была доступна только для чтения. После разрешения записи служебных каталогов CLI Codex ответил `READY`, а повторный полный сценарий дошёл до `done`. Внутренняя read-only песочница Codex по-прежнему не смогла исполнять команды; это отдельное ограничение.

Повторить сценарий после настройки авторизации:

```sh
npm run test:live -- --live --author-model claude-opus-5 --reviewer-model gpt-5.6-sol
```

Идентификаторы выше — фактически использованные в этом прогоне; в другой среде нужно выбрать доступные модели. Скрипт создаёт временный Git-репозиторий, выполняет doctor до выдачи задачи и сохраняет отчёт даже при отказе. В обычный `check` он не входит. Модельный диалог, самостоятельная декомпозиция, несколько компонентов и продуктовая приёмка доски в этом сценарии не проверяются.

## CI и браузер

Публичный API GitHub показал пять последних запусков в состоянии failure. Для исходного `71a0b7d` установка зависимостей и Chromium прошла; упал шаг `npm run check`. [Запуск CI](https://github.com/step1ov/devcontour/actions/runs/35328073444). Аннотация даёт только exit code 1; полного журнала этого шага получить не удалось. Поэтому конкретный тест, упавший в Linux, не установлен и не приписывается локальной проблеме macOS.

Локально три Playwright browser-сценария не смогли запустить Chromium: `MachPortRendezvousServer ... Permission denied (1100)`. HTTP-сценарий запускается отдельно. Полный check с таким результатом не считается зелёным. В доступном браузере дополнительно проверены загрузка графа, новое имя целевой ветки, открытие/закрытие диалога с возвратом фокуса и запуск очереди; это ограниченная проверка UI, не замена Playwright и axe.

## Что предложено вместо буквального выполнения всего ревью

**Размер пилота.** Начали с одной задачи, поскольку десять–пятнадцать задач одновременно смешали бы проблемы авторизации, инструментов, декомпозиции и качества моделей. Следующий этап — небольшой вертикальный продуктовый сценарий с backend и frontend, 3–5 связанных задач и работоспособными инструментами reviewer. После этого можно расширять выборку. До такой проверки расширение доменных возможностей не приоритетно.

**Понятия.** Вместо новой большой инвентаризации всех сущностей оставлен существующий словарь concepts.md. На входе пользователю достаточно workspace, компонента, задачи, зависимости и приёмки. Run, lease, SHA и receipt нужны при диагностике; ChangeSet — для нескольких компонентов; forge и remote completion — для публикации. Удалять эти механизмы без доказанной избыточности нельзя: они обслуживают проверяемые инварианты.

**Контекст.** START.md содержит 26 692 символа / 43 465 UTF-8 байт, skill — 10 494 символа / 10 545 байт на момент аудита. Наличие устанавливаемых руководств не означает автоматическую передачу их целиком каждой модели. Следующее упрощение — сократить стартовый маршрут и загружать подробности по текущему шагу, проверив это отдельным eval. В успешном пилоте полезная нагрузка DevContour была 2 115 байт исполнителю и 2 758 байт каждому reviewer; собственные инструкции CLI считаются отдельно.

**Изоляция исполнения.** Контейнерный executor имеет смысл, но это отдельный проверяемый срез. Точка запуска — runner/process.ts; adapters.ts готовит команды моделей, gates.ts — команды проверок. Предлагаемый первый вариант: один opt-in контейнерный runtime, worktree с тем же абсолютным путём (Git worktree содержит ссылку на общий gitdir), необходимые Git metadata с минимальными правами, отдельный volume артефактов, без доступа к SQLite controller и Docker socket. При read-only reviewer оба Git mounts доступны только для чтения. Worker получает только явно разрешённые credentials; gates не получают токены модели. Сеть управляется allowlist, зависимости готовятся заранее. Отмена убивает группу процессов/контейнер, teardown сохраняет receipt, неуспешная очистка удерживает resource lease. Это предложение, не готовая функция и не обещание изоляции текущего host mode.

**Логи.** Исторические обезличенные свидетельства остались в Git в evidence, чтобы не разрушить ссылки отчётов. Новые полные логи — артефакты CI; в Git сохраняется компактная сводка.

**Совместимость и язык.** Мигратор старого имени не добавлен по решению владельца. README и вся пользовательская документация остаются русскими, именованных сравнений с конкурентами нет.
