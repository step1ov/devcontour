# Проверка памяти, измерений и экспериментов

Дата: 18 сентября 2026 года. Среда: macOS, Node.js 24.3.0. Проверены локальные fixtures, реальные Git worktrees и независимые clones. Вызовы платных моделей, push и публикация не выполнялись.

## Состав изменения

- Измерения каждого вызова runtime: версии, токены, cache usage, источник стоимости, закреплённый тариф и полнота данных. Ошибочные вызовы и повторные попытки сохраняются у владельца; неизвестный расход не превращается в ноль.
- Типизированная память в Git компонента: источники с SHA/digest, связи поддержки и замены, актуальность, конфликты и бюджет выдачи. Исполнитель и оба reviewers получают один сохранённый снимок.
- Инженерный корпус из трёх сценариев с исполняемыми проверками на candidate/integration SHA; сравнение совместимых отчётов с повторениями и интервалом неопределённости.
- Запись входов решения scheduler и консервативный аудит фиксированных стратегий. Ненаблюдавшиеся варианты остаются unsupported; автоматического изменения production-политики нет.
- Общий CLI/HTTP/MCP API, обновлённый skill и одиннадцать руководств, переносимых через setup.

## Что именно подтверждено

Telemetry проверена на синтетических ответах Codex/Claude, включая cache counters, неполные данные, тарифные оценки и ошибочный процесс. Один тест запускает настоящий дочерний CLI-fixture с exit 1: сохраняются версия, известный расход и признак неполноты. Изменение конфигурации после начала вызова не переписывает его тариф. Это проверка нормализации, а не сверка со счётом провайдера.

Тесты памяти проверяют источники, ограничения владельца, symlinks, замену, конфликты, устаревание производных сводок и бюджет. Два независимых Git clones добавляют знания параллельно и объединяют UUID-файлы. Отдельный Git runner fixture меняет каталог после старта автора и подтверждает, что оба reviewers сохраняют исходный снимок.

Инженерный корпус действительно изменяет код, запускает Node и SQLite, сохраняет JUnit и проходит обычную проверку интеграции. Эталонный исполнитель проходит 3/3 сценария за 9 вызовов адаптера; пустой исполнитель проваливает все три. Сравнение отклоняет несовместимые бюджеты, корпуса, неполные и повторные пары случаев. Неизвестные результаты не дают положительного статистического вывода.

Тест аудита scheduler исключает недоступные зависимости, проверяет область владельца и показывает unsupported при другом выборе после retry. Изменение будущих исходов не меняет восстановленный выбор стратегии.

Форматирование, локальные ссылки документации, JSON-примеры и diff проверены отдельно. Новая память и отчёты доступны агентам через общий интерфейс; отдельных экранов консоли для них пока нет.

## Границы проверки

Fixture PASS не оценивает качество Codex/Claude и не доказывает экономию токенов на продуктовых задачах. Live-вызовы, реальные суммы провайдера, PostgreSQL, мобильные устройства, корпоративные MCP и production rollout не проверялись. Память хранит утверждения с источником, но не доказывает правильность их интерпретации. Три инженерных сценария — начальный корпус, который нужно расширять задачами своего продукта перед выбором моделей или политики.
