# Внешние сигналы и предложенная работа

Первый вход принимает нормализованное наблюдение через MCP `signal_ingest` или CLI `agent --file signal.json --workspace /absolute/workspace`. Ведущий агент либо существующий CI-адаптер читает сведения разрешёнными средствами и формирует запрос. DevContour сам не получает дополнительные права GitLab/GitHub, не открывает публичный webhook и не подключает мониторинг автоматически.

```json
{
  "operation": "signal_ingest",
  "input": {
    "source": "corporate-ci",
    "eventId": "job-42-failed",
    "incidentId": "chat-contract-regression",
    "repositoryId": "chat-library",
    "observedAt": "2026-09-17T10:00:00.000Z",
    "state": "open",
    "title": "Регрессия контракта чата",
    "summary": "Проверка совместимости ответа API выявила несовместимое изменение.",
    "evidenceUrl": "https://git.example.internal/project/jobs/42"
  }
}
```

Наблюдение создаёт component draft-задачу с требованием воспроизвести проблему. Оно не является доказательством дефекта или разрешением на публикацию. Ссылку система сохраняет, но не загружает; credentials и сырые секретные логи в summary передавать нельзя.

Для действующей доски укажите `boardId`. Для принятой доски нужны также `roots` — IDs затронутых задач текущей ревизии. Тогда используется обычная корректировка с `supersedes` и транзитивными потребителями; исходная приёмка сохраняется. Доска должна принадлежать указанному компоненту.

`eventId` идентифицирует доставку, `incidentId` — проблему. Повтор события идемпотентен; тот же ID с другим payload отклоняется. Более старое или равное по времени наблюдение не перезаписывает новое. Новое событие `state: resolved` отмечает состояние источника, но не меняет задачу на done, не добавляет PASS и не принимает доску. Повторное открытие может породить следующую корректировку.

Создание задачи/корректировки и receipt фиксируются одной SQLite-транзакцией. Ошибка DAG, владельца или rate limit откатывает оба действия. По умолчанию допускается 10 новых предложений/корректировок в час на источник и компонент; настройка — `signalPolicy.maxActionsPerHour`. Повторы и сообщения об исчезновении сигнала лимит не расходуют.

`signal_status` с `repositoryId` показывает журнал наблюдений. Тела событий и журнал находятся в локальной БД библиотеки. Сами задания переносятся обычным Git sync, receipts доставки остаются оперативными данными этого controller. Дедупликация не является глобальной блокировкой между независимыми хостами: один поток событий следует направлять одному controller.

После проверки постановки ведущий агент может включить задачу в workflow. Ни приход события, ни его исчезновение не запускают автоматически deployment, rollback или выключение обязательного теста.
