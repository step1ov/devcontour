# Проверка DevContour 0.3

Дата: 17 сентября 2026 года. Среда: macOS, Node.js 24.3.0. Проверены локальные fixtures и реальный Git; внешние модели не вызывались. Версия подготовлена как npm-архив для локальной установки; публикация в registry и push не выполнялись.

## Реализованные этапы

1. `504ed00` — разделы требований связаны с task specification, test gate/scenario и evidence на candidate/integration SHA; добавлены отчёт актуальности и корректировка. Git sync сохраняет текст у компонента.
2. `3255e79` — изолированные evals решений агента, детерминированная fixture и явно выбираемый live-режим с ограничением вызовов/времени.
3. `d2f96e1` — время стадий и ожидания, сохранение неудачных попыток, прозрачные знаменатели метрик и неизвестная стоимость.
4. `f4c8e38` — сохраняемые workflow доски и ChangeSet, leases, fencing, бюджеты и восстановление после смены процесса.
5. `6f1104e` — внешние наблюдения превращаются в локальные draft-задачи или корректировки; дедупликация, порядок событий и лимит предложений.

Завершающая правка добавляет обработку удалённого входа workflow без блокирования других jobs, проверку установленного пакета, обновлённые skill/справочники и версию 0.3.0.

## Что доказывают проверки

Дополнительно прошли `npm run format:check`, `git diff --check` и проверка локальных ссылок изменённой Markdown-документации.

Тесты требований показывают, что committed-изменение раздела делает старое покрытие неактуальным, новый draft сохраняет историю, а неверный текст в candidate блокирует приёмку. Проверки Git sync используют независимые clones и проверяют локальность данных.

Workflow fixture заменяет процесс после уже совершённого review, затем продолжает на том же SQLite без повторного утверждения. Реальные task gates, Git-интеграция, board acceptance и общий ChangeSet доходят до завершения. Отдельно проверены просроченный владелец, stale input, operator mode, явная пауза и атомарный rollback.

Сигналы проверяются на дубликат, конфликт payload, запоздавшее событие, разрешение инцидента и превышение лимита. `resolved` не превращает задачу в `done`. Проверка физической компонентной БД подтверждает, что подробности наблюдения не записаны в coordinator.

Evals проверяют реальное применение разрешённых операций и обнаруживают намеренно ослабленный driver. Fixture PASS подтверждает работу evaluator, а не качество Codex/Claude. Реальные модели, стоимость, корпоративные MCP, устройства, CI-наблюдение и production-публикация в этом запуске не проверялись. Live-eval остаётся отдельным явным запуском по [инструкции](agent-evals.md).
