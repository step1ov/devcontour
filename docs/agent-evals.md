# Проверка поведения агентов

`devcontour evals` выполняет шесть изолированных сценариев: цикл DAG, устаревшее редактирование, изменившийся checkpoint, попытка принять работу без evidence, локальность задания компонента и недоступная обязательная проверка. Каждый случай получает временный Git-репозиторий и component SQLite. Действия проходят через настоящий прикладной слой; итог оценивает отдельный проверяющий код.

По умолчанию работает **детерминированный protocol fixture**, без модели и provider credentials. Это проверяет механизм оценки и ожидаемые действия, но не подтверждает качество Claude/Codex. Негативный тест подставляет заведомо слабую стратегию и требует обнаружить регрессии.

Из исходников эквивалентная команда — `npm run test:evals`. Продуктовый `--workspace` не нужен: evaluator создаёт и удаляет собственные временные репозитории. Обычный `npm test` также проверяет положительный driver, намеренно слабую стратегию, лимиты и ошибки runtime.

Реальная проверка запускается явно:

```sh
devcontour evals --live --runtime codex --model MODEL_ID --repetitions 3 --max-calls 18 --timeout-ms 120000
```

`--runtime claude` использует другой адаптер. `--instructions /absolute/skill.md` позволяет сравнить изменение правил с исходным skill. Агент возвращает структурированное решение и последовательность действий; evaluator исполняет только ограниченный набор операций контекста и черновиков. Очередь, публикация и произвольная приёмка недоступны. Это оценка решения в заданном состоянии, не измерение полного многотурового выполнения продукта.

| Параметр        | По умолчанию | Граница                                    |
| --------------- | ------------ | ------------------------------------------ |
| `--repetitions` | 1            | 1–10 повторений каждого из шести случаев   |
| `--max-calls`   | 6            | 1–60 ответов driver/runtime на весь запуск |
| `--timeout-ms`  | 120000       | 1000–900000 мс на внешний вызов runtime    |

Для полного корпуса нужно не меньше `6 × repetitions` вызовов: повышение repetitions без бюджета даст unverified, а не частичный PASS. Сам runtime внутри одного вызова может выполнять несколько model turns; это не точный счёт API-запросов или токенов провайдера. `--runtime`/`--model` без `--live` отклоняются. Для сравнения моделей укажите model явно: без него выбор остаётся у CLI runtime.

Отчёт содержит результаты каждого повторения, digests корпуса, инструкций, skill и каталога инструментов, runtime/model и доступную runtimeVersion, длительность и расход вызовов. Лимит вызовов и таймаут ограничивают работу; денежный лимит задаётся у провайдера, `costUsd: null` означает отсутствие измерения. Пропущенный по бюджету или недоступный запуск — `unverified`, общий exit code ненулевой. Все случаи должны пройти, чтобы получить PASS.

Сравнивайте одинаковые corpus/catalog digests и число повторов. Изменение модели или правил не следует принимать по одному удачному ответу. Сырые ответы и provider logs удаляются вместе с временными fixtures; отчёт не содержит полных диалогов. Примеры из настоящих инцидентов добавляются после обезличивания и независимого определения ожидаемого результата.

## Выполнение кода и сравнение

`engineering-evals` дополняет эти проверки тремя задачами с реальными Git worktrees, candidate/integration gates и исполняемым oracle. `eval-compare` сопоставляет отчёты при одинаковых входах и бюджетах. Полный порядок и ограничения — в [экспериментах](experiments.md). Live `evals` также собирает доступную runtime telemetry; отсутствие данных остаётся null.

`--prices /absolute/prices.json` также доступен в `evals`: это JSON-массив тарифов из формата конфигурации. Отчёт сохраняет priceTableDigest; сравнивайте расходы при одинаковых тарифных предположениях.
