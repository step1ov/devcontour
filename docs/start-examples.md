# Примеры запуска через CLI и skill

Выберите удобный вход: запустить панель командой и передать её ведущему агенту либо сразу поручить агенту весь запуск. Оба маршрута используют один CLI и одинаковый процесс: продукт → ваше утверждение → архитектура, стек и C1/C2 → ваше утверждение → разработка.

Все пути `/absolute/...` ниже — примеры: замените их своими абсолютными путями. Workspace должен находиться вне установки DevContour. Для одного Git-репозитория или монорепозитория выбирайте `embedded`, для координации самостоятельных репозиториев — `separate`. [Подробное сравнение](workspace-modes.md).

## Через CLI из репозитория DevContour

Нужны Node.js 24.3+ и Git. Подготовьте установку один раз:

```sh
cd /absolute/devcontour
npm ci
npm run build
```

После этого выполните **один** из следующих примеров. Сервер работает в текущем терминале до `Ctrl+C`; при запуске агентом он остаётся в управляемой фоновой сессии.

### Один проект или монорепозиторий

```sh
npm run devcontour -- start \
  --workspace-mode embedded \
  --workspace /absolute/shop \
  --port 0
```

Корень `shop` становится workspace. Приложения, сервисы и внутренние пакеты остаются каталогами одного Git; переносимая память и локальная SQLite находятся в этом же проекте. На первом запуске Git и структура приложения ещё могут отсутствовать.

### Несколько самостоятельных репозиториев

```sh
npm run devcontour -- start \
  --workspace-mode separate \
  --workspace /absolute/shop-workspace \
  --port 4317
```

Общая координация находится в `shop-workspace`; например, код продукта — в `/absolute/shop`, библиотеки — в `/absolute/chat-library`. Их пути передайте агенту. После утверждения архитектуры он подготовит реестр по [руководству нескольких репозиториев](workspaces.md).

### Установленный npm-пакет

Если CLI уже установлен из [архива DevContour](distribution.md), исходники и сборка не нужны. Команда для того же embedded-проекта:

```sh
devcontour start \
  --workspace-mode embedded \
  --workspace /absolute/shop \
  --port 0
```

Для separate замените режим на `separate`, а workspace — на `/absolute/shop-workspace`. Остальные параметры совпадают. При локальной установке вызывайте executable `node_modules/.bin/devcontour` из каталога инструментов.

### Опции команды start

| Опция                                      | Что задаёт                                                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `--workspace /absolute/path`               | Обязательный абсолютный путь. В embedded это корень единственного репозитория; в separate — отдельная папка координации.                   |
| `--workspace-mode embedded` или `separate` | Обязательный выбор для нового workspace. Сохраняется в `devcontour.workspace.json`; при продолжении флаг можно опустить.                   |
| `--port 0`                                 | Свободный порт выбирает ОС; фактический URL появится в выводе команды.                                                                     |
| `--port 4317`                              | Конкретный порт; `4317` используется по умолчанию. Если порт занят, выберите другой.                                                       |
| `--dev`                                    | Vite middleware при разработке самого DevContour из исходников. Для обычной работы над продуктом используйте собранный UI без этого флага. |

Проверяйте URL, режим и путь в выводе и панели. `start` поднимает сервер и локальное состояние, но сам не читает ТЗ и не запускает модель-планировщик. `--brief`, `--profile`, `--approval-mode` и названия моделей не являются настройками `start`: их место описано ниже.

### Продолжить работу после остановки

Из той же установки запустите сохранённый workspace:

```sh
npm run devcontour -- start --workspace /absolute/shop --port 0
```

В установленной версии замените `npm run devcontour --` на `devcontour`. Режим и данные сохраняются; при `--port 0` адрес может измениться. Если сервер уже работает, используйте его URL. Второй сервер для того же workspace не нужен. Передача другого режима не переносит существующие данные: миграция между размещениями пока не реализована.

После самостоятельного запуска передайте агенту:

> Продолжи работу через DevContour. Workspace: /absolute/shop. ТЗ: /absolute/shop/docs/spec.md. Панель уже запущена: URL из вывода start. Проверь её принадлежность workspace и используй существующий сервер. Проработай продукт, затем архитектуру и стек с C1/C2; получи моё утверждение каждой из этих частей в панели. После этого веди разработку и проверки.

Вместо слов «URL из вывода start» вставьте реальный напечатанный адрес.

## Через skill ведущего агента

Подключите skill `devcontour` в своём AI-клиенте и выберите его для поручения. Путь к каталогу skill можно узнать командой:

```sh
# В репозитории DevContour:
npm run devcontour -- skill-path
# В установленной версии:
devcontour skill-path
```

Эти команды только печатают путь. Способ подключения skill зависит от клиента; подробности — [MCP и переносимый skill](mcp-server.md#skill). Skill содержит инструкции: ведущий агент читает их и выполняет тот же CLI через терминал. Сам skill сервером не является, MCP для такого запуска не обязателен.

### Новый монорепозиторий, технические согласования у агента

Скопируйте поручение и замените пути:

```text
Используй skill devcontour для разработки проекта Shop.
ТЗ: /absolute/shop/docs/spec.md.
Размещение: embedded. Workspace и репозиторий: /absolute/shop.
Запусти панель на свободном порте (--port 0), сообщи URL и оставь сервер работающим.
Проработай продуктовую часть и получи моё утверждение в панели.
Затем подготовь архитектуру, стек и C1/C2 и получи утверждение.
Затем референсы, а если изменение касается интерфейса — концепт и дизайн-систему; каждый шаг утверждаю я.
После всей цепочки самостоятельно настрой профиль, контракты, задачи и проверки.
Дополнительные технические согласования: agent.
Claude Code реализует задачи, Codex выполняет независимое ревью.
Публикацию и push выполняет человек.
```

Здесь выбранные CLI должны быть установлены и авторизованы к началу исполнения. Настройка их ролей выполняется агентом в конфигурации после согласований; наличие названия модели в поручении само по себе не подтверждает её доступность.

### Продукт и отдельная библиотека, ручные технические согласования

```text
Используй skill devcontour для развития существующего продукта.
ТЗ: /absolute/shop/docs/admin-spec.md.
Размещение: separate. Workspace: /absolute/shop-workspace.
Репозитории: /absolute/shop и /absolute/chat-library.
Запусти панель на порте 4318 и сообщи URL.
Изучи существующие правила и код; сохрани задачи и знания библиотеки в ней.
Проработай продукт, затем архитектуру и стек с C1/C2.
Дождись моего утверждения каждой части в панели.
После этого подготовь общий реестр и зависимости задач между репозиториями.
Дополнительные технические согласования: operator.
Публикацию и push выполняет человек.
```

В `operator` пользователь дополнительно подтверждает технические контракты, планы и приёмку. В `agent` эти действия выполняются агентом по правилам независимого ревью. **Оба режима требуют двух начальных пользовательских решений и настоящих проверок.**

### Выбор размещения ещё не сделан

> Используй skill devcontour. ТЗ: /absolute/shop/docs/spec.md. Перед запуском объясни варианты embedded и separate, помоги выбрать размещение и уточни абсолютный путь workspace. Дождись моего выбора, затем запусти панель и начни продуктовую проработку.

Агент спрашивает только недостающие сведения. Если выбор уже сохранён для указанного workspace, повторное согласование размещения не требуется.

### Возобновить работу в новой сессии

> Используй skill devcontour и продолжи проект в workspace /absolute/shop. Прочитай сохранённый режим, состояние подготовки, переносимую память и checkpoint. Проверь работающий сервер; если он остановлен, запусти start для этого workspace и сообщи URL. Продолжи с актуального этапа, сохрани принятые решения и историю задач.

Для нового Git clone дополнительно требуется восстановление локальной конфигурации и [синхронизация памяти](team-sync.md). Возобновление сессии на прежнем компьютере и восстановление clone — разные процедуры.

## Агент открыт в репозитории DevContour, skill не установлен

В этом случае агенту доступны `AGENTS.md` и [START.md](../START.md). Достаточно поручения:

> Прочитай START.md и веди разработку через DevContour. ТЗ: /absolute/shop/docs/spec.md. Размещение: embedded. Workspace: /absolute/shop. Сразу запусти панель на свободном порте и сообщи URL. Затем последовательно подготовь продукт, архитектуру со стеком и C1/C2, референсы и — если изменение касается интерфейса — концепт и дизайн-систему; каждую версию утверждаю я. После всей цепочки веди реализацию и проверку.

Открытие каталога само по себе запуск не вызывает. В установленном клиенте можно использовать skill; при работе из исходного репозитория правила уже направляют агента к тому же процессу.

## Какие настройки передавать агенту

| Пожелание                                        | Где применяется                                                                                                             |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| Путь к ТЗ, существующему коду и библиотекам      | В поручении агенту; он читает материалы и готовит постановки.                                                               |
| Размещение и путь workspace                      | В `start --workspace-mode ... --workspace ...`.                                                                             |
| Свободный или конкретный порт панели             | В `start --port ...`.                                                                                                       |
| Выбранный стек и профиль                         | После утверждения архитектуры — `setup --profile ...` либо реестр нескольких репозиториев.                                  |
| Дополнительные технические согласования          | При первом `setup` — `--approval-mode agent` или `operator`; в существующем проекте агент осознанно обновляет конфигурацию. |
| Кто реализует и кто проверяет, конкретные модели | Политика ролей/runtime в конфигурации проекта; [правила выбора моделей](configuration.md).                                  |

Например, **после обоих утверждений**, если для embedded-админки согласован React/Vite, агент может выполнить:

```sh
npm run devcontour -- setup \
  --repository /absolute/shop \
  --workspace /absolute/shop \
  --profile react-vite-admin \
  --brief docs/spec.md \
  --approval-mode agent
```

`--brief` здесь указывает документ относительно репозитория; `--approval-mode operator` добавит ручные технические подтверждения. При повторном setup существующий режим согласования сохраняется. Для другого стека агент выбирает соответствующий профиль или создаёт собственный. Setup подключает техническую конфигурацию к уже работающей панели; каркас, реальные тесты и задачи агент готовит по [START.md](../START.md).
