# Preview: попробовать проверенный результат

Принятый commit и зелёные проверки — ещё не то, что оценивает автор продукта. Ему нужен работающий сервис. Preview собирает проверенный ChangeSet и запускает его локально в Docker по постоянному адресу `http://127.0.0.1:<port>`.

Это один путь для одного стека: локальный Docker с `docker compose`. Production-поставка и облачные среды этим не заявляются.

## Что выкладывается

Только то, что прошло совместную проверку ChangeSet. Корень сборки собирается из manifest этой проверки: каждый компонент берётся на проверенном SHA через `git archive` и кладётся в каталог `<repositoryId>/`. Незакоммиченные файлы рабочих копий в образ не попадают.

Идентификатор релиза вычисляется из digest manifest (`r` и 12 символов). Им названы compose-проект и образы. Он передаётся в сборку как `DEVCONTOUR_RELEASE`, чтобы приложение могло назвать свою версию.

## Настройка

Раздел `preview` в конфигурации workspace:

```json
{
  "preview": {
    "compose": "app/compose.preview.yml",
    "service": "web",
    "port": 4400,
    "health": { "path": "/health", "timeoutMs": 60000 },
    "version": { "path": "/version" },
    "smoke": { "command": ["node", "app/scripts/smoke.mjs"], "timeoutMs": 300000 },
    "environment": { "secrets": { "SESSION_SECRET": "PREVIEW_SESSION_SECRET" } }
  }
}
```

Compose-файл лежит в одном из компонентов. Относительные пути в нём считаются от корня сборки, поэтому контекст компонента указывается как `./<repositoryId>`. Входной сервис публикует порт на `${DEVCONTOUR_PREVIEW_PORT}`:

```yaml
services:
  web:
    build:
      context: ./app
      args:
        DEVCONTOUR_RELEASE: ${DEVCONTOUR_RELEASE}
    ports:
      - '127.0.0.1:${DEVCONTOUR_PREVIEW_PORT}:8080'
```

`version.path` необязателен, но полезен: с ним принадлежность URL новому релизу подтверждает ещё и само приложение. `smoke` — пользовательский сценарий против адреса из `PREVIEW_URL`. Он исполняется в той же песочнице, что и проверки: сеть — только localhost. Окружение сборки и запуска — только явно перечисленное, секреты передаются по имени.

`doctor` проверяет доступность Docker и Compose, если preview настроен.

## Запуск и откат

```sh
devcontour preview --changeset CHG-1 --workspace /absolute/workspace
devcontour preview-rollback --workspace /absolute/workspace
```

В панели то же выполняется кнопкой. Агент видит состояние операцией `preview_status`. Выкладка и откат — отдельные контролируемые действия, агентские операции их не запускают.

## Порядок выкладки

1. Сборка образов из manifest. ID образов записываются как артефакт релиза.
2. Пробный запуск на временном порту: health и сверка версии. Прежний релиз в это время продолжает обслуживать URL.
3. Прежний релиз останавливается, но не удаляется. Новый занимает публичный порт и проверяется снова, включая то, какой compose-проект держит порт.
4. Если на публичном порту проверка не прошла, новый релиз снимается, а прежний запускается снова.
5. Пользовательский сценарий против URL.

Ни один отказ не выглядит готовностью. Ошибка сборки или здоровья оставляет URL прежнему релизу.

## Состояния

| Состояние   | Что означает                                                       |
| ----------- | ------------------------------------------------------------------ |
| building    | Сборка идёт                                                        |
| built       | Образы собраны из проверенного manifest                            |
| deployed    | Релиз занял публичный порт                                         |
| healthy     | Health и принадлежность URL подтверждены                           |
| confirmed   | Пользовательский сценарий прошёл на URL                            |
| unconfirmed | Релиз здоров и обслуживает URL, но сценарий не прошёл или не задан |
| failed      | Релиз не выложен; URL обслуживает прежний                          |
| retired     | Релиз снят с URL                                                   |

Проверка ChangeSet («код проверен») и его приёмка — отдельные состояния самого ChangeSet. Preview их не заменяет и из них не выводится.

Повтор выкладки того же manifest ничего не собирает: возвращается уже обслуживающий релиз. Одновременно идёт не больше одной выкладки. Попытка, чей процесс умер, после истечения lease считается проваленной.

## Данные и миграции

У каждого релиза свой compose-проект и свои volumes. Данные preview одноразовые: новый релиз стартует на пустых данных своих сервисов, а миграции проверяются с нуля. Прежний релиз хранится остановленным вместе с данными, чтобы откат вернул его как было. Более старые релизы удаляются вместе с данными.

Перенос данных между релизами, обратимость миграций на накопленных данных и production-базы — не предмет preview. Для них нужна отдельная процедура.
