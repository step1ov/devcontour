# Проверка подключаемых профилей

Дата: 18 сентября 2026 года. Среда: macOS, Node.js 24.3.0 и установленный Python 3. Вызовы моделей, push и публикация не выполнялись.

## Что изменилось

Профиль можно подключить из репозитория компонента через setup, init и workspace-init. Расширение списка стеков не требует изменения DevContour: JSON с extends собирает отдельные части стека, проверок и окружения. Команда profile-show показывает результат без выполнения проектных команд. Lock фиксирует весь состав; конфигурация различает одинаковые IDs разных владельцев и сохраняет явно настроенную политику при повторном setup.

Добавлены стартовые python-api, nest-api, react-native, expo-mobile и переиспользуемый node-checks. Прежние встроенные manifests и их digests сохранены. Роли, модели, права инструментов и условия приёмки остаются отдельными настройками.

## Что подтверждают тесты

Resolver проверен на локальном составе stack/checks/environment, повторной ссылке на одну часть, цикле, недопустимом пути, symlink, слишком большом файле, неизвестной зависимости gate, конфликте команд и окружения, попытке передать approvalMode, недопустимом параллелизме и отсутствии JUnit. Некорректный состав отклоняется до копирования правил проекта. Просмотр профиля не создаёт workspace и не запускает команды.

Setup сохраняет настройку gate, изменённую пользователем, при повторном вызове. Изменение наследуемого файла делает lock устаревшим и останавливает загрузку; новая версия не применяется автоматически. Окружение single-component workspace сохраняется у компонента, а не становится общей настройкой.

Два независимых Git clones используют одинаковый ID профиля с разными настройками окружения. Их записи lock различаются владельцем; общая конфигурация не содержит локальных значений окружения. Перенос исходных файлов в другой путь не меняет digest состава. Изменение библиотечной части обнаруживается отдельно от продукта.

Сквозной Git fixture использует настоящий процесс Python и исполняемую проверку содержимого файла и окружения с JUnit XML. Сначала намеренно пустой writer получает отказ. Затем writer исправляет значение, и задача проходит candidate/integration проверки и независимые fixture-review. Отдельная попытка изменить файл профиля отклоняется как запись в защищённый путь. Модели в этом тесте заменены явно заданными детерминированными исполнителями.

Проверка npm-архива выполняется без src/tsx в установленном пакете. Она разрешает новые встроенные профили, устанавливает собственный профиль с наследованием, вызывает общий API и подтверждает отказ после изменения зависимой части. После восстановления файла обычный workflow проходит реальную локальную Git-приёмку.

## Границы результата

Подтверждены универсальный механизм команд, композиция, фиксация версий, установка и сохранение условий приёмки. Стартовый manifest задаёт команды, но не реализует приложение и не устанавливает все внешние инструменты. Полноценные NestJS, React Native/Expo, uv/pytest-проекты, устройства, EAS и корпоративные сервисы в этом прогоне не запускались. Для них ведущий агент должен подготовить окружение и выполнить проектный сквозной пилот. Это также относится к новым стекам, подключаемым через собственный профиль.

Использование: [профили, модели и MCP](mcp-and-profiles.md).
