# DevContour

DevContour — локальная система разработки с AI-агентами. Она превращает согласованный граф задач в проверенные изменения: отдельный Git worktree для каждой попытки, обязательные тесты, независимое ревью, повторная проверка интеграции и сохранённые доказательства результата.

Ведущий агент ведёт продукт от ТЗ до приёмки; DevContour управляет исполнением и проверяет условия завершения. Поддерживаются Codex и Claude Code, несколько репозиториев продукта и библиотек, локальная веб-консоль и чтение статуса публикации в GitLab/GitHub или другой forge через адаптер.

## Посмотреть demo

Нужны Git и Node.js 24.3 или новее. Выполняйте команды из каталога DevContour:

```sh
npm ci
npm run build
npm run demo
```

Откройте [DevContour Console](http://127.0.0.1:4317), запустите очередь и изучите проверки задачи. Demo использует настоящие локальные Git-операции и детерминированные исполнители; модели и их credentials не нужны. Учебные данные находятся в `.harness/demo/` самой установки. Подробный учебный маршрут и остановка — в [быстром старте](docs/quickstart.md).

## Начать реальный продукт

Положите ТЗ в `docs/spec.md` продукта и дайте ведущему агенту поручение:

> Прочитай START.md в DevContour. Реализуй ТЗ продукта по пути /absolute/product/docs/spec.md. Workspace: /absolute/product-workspace. Сам подготовь проект, контракты, граф задач и проверки, запусти веб-консоль и веди разработку до проверенного результата. Согласования этапов отключены; внешнюю публикацию выполняет человек.

Если workspace не указан, агент обязан один раз спросить его абсолютный путь. Настройка продукта, роли и выбор профиля — работа агента. По умолчанию `approvalMode: agent`; опциональный `operator` добавляет подтверждения этапов. Тесты и независимое ревью обязательны в обоих режимах.

Требуется активная сессия ведущего агента. Появление файла в `docs` само по себе ничего не запускает. `setup` переносит правила и конфигурацию; каркас приложения, реальные сценарии тестирования и дальнейшее планирование готовит агент.

## Где находятся код и состояние

```text
devcontour/                 # установка инструмента
product-workspace/         # общая координация, контракты, ChangeSet и дневник
product/                   # Git продукта, локальные задачи/попытки/журнал
shared-library/            # Git библиотеки, её правила, память и локальное состояние
```

Продуктовая работа не меняет установку DevContour. В новом workspace используется `storage: component`: подробные задачи и попытки хранятся в SQLite внутри соответствующего репозитория, общий граф собирается по ссылкам. Один controller работает на одном хосте с максимум 10 компонентами и 1–4 workers. Worktree изолирует Git-изменения; общей защиты от произвольного кода он не предоставляет.

Независимые проекты могут использовать одну установку с разными workspace и портами. Продукты, совместно изменяющие одну библиотеку, объединяются в один workspace. [Обоснование границ](docs/decisions.md).

## Что означает готовность

`done` означает, что задача проверена на candidate и интеграционном SHA и принята в локальную ветку `harness/accepted`. Приёмка доски фиксирует ревизию. ChangeSet отдельно подтверждает совместимость набора версий продукта и библиотек. В `completionMode: remote` приёмка ChangeSet дополнительно требует подтверждённых merge и CI.

Push, создание PR/MR, merge и публикацию пакетов выполняет человек. DevContour готовит handoff и читает результаты. Изменение принятого результата создаёт новую ревизию с `supersedes`; история остаётся доступной. [Условия приёмки и границы MVP](docs/mvp.md).

## Разработка инструмента

```sh
npm run dev
# В отдельном терминале после установки браузера:
npx playwright install chromium
npm run check
```

`check` включает проверку цветовых токенов, TypeScript/Vite build, unit/Git integration tests и Playwright E2E. Форматирование проверяется отдельно: `npm run format:check`. Доступность тестовых инструментов обязательна: отсутствие браузера не считается PASS.

[Руководство разработчика](docs/development.md) объясняет структуру кода, выбор тестов и добавление возможностей. [Архитектура](docs/architecture.md) описывает инварианты и восстановление после сбоев. Исторические [отчёты проверок](docs/index.md#отчёты-проверок) отделяют выполненные fixture-проверки от непроверенных live-интеграций.

## Имя и совместимость

Название продукта и npm package — `devcontour`; основная команда — `npm run devcontour -- <команда>`. `npm run harness` остаётся алиасом. Служебные имена `.harness/`, `harness.component.json`, ветки `harness/*`, переменные `HARNESS_*`, заголовок `X-Harness-Request` и установленные документы `harness-*.md` сохранены для совместимости существующих workspace. Переименование бренда не требует миграции данных.
